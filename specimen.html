      CONTENTS

        This specimen demonstrates the approved typography, metadata, contents, figures, tables, equations and references. Its example values and diagrams are illustrative. Use it to select components; start a new paper from the shorter starter.

        Start with the reader

        A technical whitepaper needs to support two kinds of reading. A specialist may read the argument closely, checking assumptions and following the evidence. A decision-maker may begin with the summary, inspect a figure, and move directly to limitations or next steps. Both readers need a clear hierarchy and reliable references.

        This example demonstrates the revised house style. The central prose column stays comfortable to read, while figures and tables have room to carry detail. Headings and paragraphs use Newsreader. Captions, tables and metadata use IBM Plex Sans.

        One source, two reading modes

        The web article provides a contents list and captions alongside figures when space allows. On small screens, the contents list collapses and captions move below their figures. The printed version uses a single column, captions below each figure, and page numbers.

        A flexible opening

        The metadata row always includes authors and a date. Without an optional label, those fields divide the row equally. A long author list receives approximately seventy percent of the width, leaving the rest for the date. Names wrap rather than shrinking.

        An optional category identifies the document as a Research Paper, Technical Report, Concept of Operations, Case Study, White Paper, Analysis or Proposal. A custom label can describe a one-off document. Distribution is a separate optional field: Public, Internal, Proprietary or Confidential. Internal, Proprietary and Confidential also appear in the footer; Public does not.

        The summary can sit on a very light background or remain unshaded. Both versions use the same typography and text. The distinction should be tested with the actual length of a document’s summary.

        Make technical information legible

        A reader should be able to interpret a chart or table without repeatedly searching the prose for definitions. Put units in column headings, identify illustrative data, and give captions enough information to explain what the reader should notice.

        Measure figure text at its final size

        An SVG’s drawing units are not printed points. For a figure with printed width W and viewBox width V, a label sized f in drawing units prints at:

        fprint=WVf(1)

        At a printed width of 496.8 points and a viewBox width of 700 units, a 12-unit label prints at approximately 8.5 points. Check the rendered PDF at reading size before deciding that a label is large enough.

        Raster images and scientific fields

        Figure 4 uses a PNG to demonstrate a raster field. Preserve meaningful color and scales in real scientific maps; supply alt text and enough resolution for the final print size. This example is a synthetic grayscale field with arbitrary coordinates, not a measured weather product.

        Appendix A: Supporting detail

        Appendix figures and tables use their own lettered sequences: Figure A-1 and Table A-1, restarting at B-1 in Appendix B. Appendices follow normal page flow. Add a deliberate page break only when a particular document calls for a separate major part.
